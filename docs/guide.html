Mode d'emploi complet · août 2026

Piloter un projet de vibe coding avec un architecte et un exécutant séparés

Ce dépôt sépare radicalement la conception de l'exécution. Un Master Agent raisonne, audite, spécifie et juge. Un exécuteur local implémente à la lettre et rend des comptes. Le dépôt Git est le seul canal entre eux — et tu redeviens l'arbitre au lieu d'être la courroie de transmission.

1 · Le principe

Un agent puissant coûte cher et raisonne bien. Un agent local coûte peu et exécute bien. Les faire travailler ensemble suppose de résoudre trois problèmes, et ce dépôt ne fait rien d'autre :

Problème 1

Aucun lien direct

Le Master ne peut pas parler à ton IDE. Réponse : ils partagent un dépôt, pas une connexion. Tout est un fichier versionné.

Problème 2

La dérive de l'exécutant

Un modèle plus faible improvise dès que la spec a un trou. Réponse : périmètre déclaré, interdits explicites, marqueur de fin obligatoire, et un CI qui refuse le travail non conforme.

Problème 3

Le quota du Master

Chaque réveil coûte. Réponse : le CI filtre en amont, les logs vivent dans le dépôt, et les audits passent par un digest condensé.

La règle qui gouverne tout le reste

Toute règle d'architecture doit avoir un outil qui la fait respecter. Une frontière que seul un document décrit sera franchie ; une frontière qu'un linter vérifie ne le sera jamais deux fois. C'est ce qui libère le Master du travail de relecture mécanique.

3 · Le cycle d'une passe

  1 AUDIT      le Master lit le dépôt (API GitHub + digest) ──► .agent/reports/
  2 PLAN       découpage en passes ──────────────────────────► .agent/BACKLOG.md + issues
  3 SPEC       périmètre, tâches, définition de fini, budget ─► .agent/passes/PASS-NNN.md
  4 DÉCLENCHE  toi : label pass:go  ou  POST /pass sur l'exécuteur
  5 EXÉCUTE    agy travaille sur pass/NNN, dans un git worktree isolé
  6 RAPPORTE   .agent/runs/PASS-NNN.run.md  +  marqueur PASS-DONE / PASS-BLOCKED
  7 VÉRIFIE    CI : tests · lint · secrets · architecture · conformité du rapport
  8 JUGE       le Master lit diff + rapport + CI
  9 VERDICT    ✅ merge   │   ⚠️ merge + dette inscrite   │   ❌ passe correctrice NNNb
  10 MÉMOIRE   STATE.md, BACKLOG.md, et un ADR si une décision a été prise

Les étapes 6 et 7 ne sont jamais sautées : un résultat non vérifié n'est pas un résultat.

5 · Windows : où faire tourner l'exécuteur

À lire avant d'installer quoi que ce soit sur Windows

Sur Windows 11 avec PowerShell 7, agy -p ne perd pas seulement son stdout : le mode print échoue aussi à réutiliser la session authentifiée et part en timeout OAuth, alors que la même machine lance l'interface interactive sans difficulté. La cause documentée : agy invoque en interne PowerShell 5.1, dont Write-Host contourne le pipeline standard et disparaît dès qu'aucune console n'est attachée. Et le contournement pseudo-TTY (script) n'existe pas sur Windows — ni en PowerShell, ni dans Git Bash.

Environnementscript (pseudo-TTY)Verdict
PowerShell natifabsentexclu stdout perdu, auth en timeout
Git Bash / MSYS2absent du paquet Git for Windowsexclu
WSL2 (Ubuntu)fourni par util-linuxrecommandé
devcontainer (Docker Desktop)ouivalable — mais Docker Desktop s'appuie déjà sur WSL2

Le choix de WSL2 n'est pas un pis-aller : tu retrouves un agy qui se comporte comme documenté, et le même environnement que le devcontainer et le CI — exactement la cohérence à trois surfaces que ce kit recherche. Antigravity reste ton IDE côté Windows et sait ouvrir un dossier WSL, donc tu ne perds rien en confort d'édition.

Quatre règles non négociables
  
1. L'URL est publique : le jeton est ta seule barrière. Traite-le comme un mot de passe,
  ne le colle jamais dans une conversation ni dans un commit.

  2. Le serveur n'exécute que des commandes d'une liste blanche — aucune chaîne
  reçue n'atteint un shell. N'ajoute jamais de route « exécute cette commande arbitraire ».

  3. Coupe le tunnel quand tu ne travailles pas.

  4. L'exécuteur écoute sur 127.0.0.1, jamais sur 0.0.0.0.

Pourquoi ce garde-fou compte
  
Un exécuteur qui échoue peut être tenté de « réussir » en désactivant un test ou en corrigeant
  la règle plutôt que le code. Ici, il n'a pas le droit d'écrire dans les workflows ni dans le contrat,
  et le CI le vérifie. Il ne peut pas s'auto-absoudre.

13 · Usages possibles

  
Le pipeline ne sert pas qu'à écrire du code. Voici ce que tu peux me demander, et par quel canal.


  

    
Audit
Diagnostic complet du dépôt

      
« Audite le dépôt, priorité sécurité. » Je condense le code via tools/digest.sh,
      je produis un rapport dans .agent/reports/, et je te remonte les points classés
      par gravité et coût de correction.

    
Architecture
Concevoir ou redresser une structure

      
J'écris ARCHITECTURE.md et les ADR, puis je traduis chaque frontière en règle
      exécutable. L'architecture cesse d'être un document et devient un test.

    
Debug
Diagnostic d'un bug tenace

      
Je lis la trace, je formule des hypothèses, j'envoie des passes d'instrumentation ciblées,
      je lis les logs de run, et je réduis l'espace de recherche jusqu'à la cause.

    
Refactor
Chantier découpé en passes

      
Une migration lourde devient dix passes bornées, chacune avec son périmètre, sa définition
      de fini et son budget. Le CI valide chaque étape avant la suivante.

    
Revue
Verdict sur le travail de l'exécutant

      
Je lis le diff, le rapport et le CI, puis je tranche : validé, validé avec dette inscrite,
      ou recadrage avec une passe correctrice pointant fichier et ligne.

    
Pilotage
Backlog vivant et mémoire de projet

      
BACKLOG.md, STATE.md et les ADR font que rien n'est rediscuté deux fois
      et qu'aucune dette n'est oubliée.

    
Démarrage
Projet neuf

      
Je pose l'architecture, l'arborescence, les règles de CI et les cinq premières passes
      avant qu'une seule ligne de code métier soit écrite.

    
Bilan
Rapports périodiques

      
Sur un tick planifié : ce qui a bougé, ce qui a dérivé, la dette accumulée, et ce que je
      recommande pour la semaine.

15 · Économie de quota

  
Six règles. Elles ne sont pas cosmétiques : elles décident du nombre de passes que ton quota finance.

  
    
    
  1. Aucun code collé dans la conversation. Une référence src/auth/x.ts:40-90 suffit : je vais chercher le contenu par l'API.
    2. 
    
  2. Les logs vivent dans le dépôt, dans .agent/runs/ — jamais dans le chat.
    3. 
    
  3. Le CI filtre avant moi. CI rouge → l'exécuteur corrige seul, je ne suis pas convoqué.
    4. 
    
  4. Passes larges, peu nombreuses. Un aller-retour avec moi doit valoir plusieurs heures d'exécution.
    5. 
    
  5. Un digest, pas un dump, pour tout audit large.
    6. 
    
  6. Réveils sur événement utile seulement : PR verte, blocage, tick planifié.
    7. 
  

  
Le partage du travail
  
Je juge la conception, les frontières, les abstractions, la dette et la cohérence avec les décisions
  passées. Le CI juge le formatage, le lint, les secrets, le code mort, les types et la couverture.
  Si quelque chose de mécanique m'atteint deux fois, la bonne réponse est une nouvelle règle de CI,
  pas une relecture de plus.

17 · Réutiliser le gabarit sur chaque projet

  
Ce dépôt est un gabarit, pas un projet. La bonne méthode n'est pas de le cloner
  puis de renommer le dossier — c'est d'en faire un template repository.


  

    
MéthodeHistoriqueRemoteRisque

    
      
clone + renommagehérite des commits du gabarit
        origin pointe encore le gabarit
        élevé un git push distrait pollue le gabarit

      
template repositoryvierge, premier commit propre
        origin = ton nouveau dépôt
        nul

    


  
Une fois pour toutes

  
Sur le dépôt du gabarit : Settings → General → cocher « Template repository ».


  
Puis, à chaque nouveau projet

  
bash
gh repo create mon-nouveau-projet \
  --template amichiamine/master-agent-pipeline --private --clone
cd mon-nouveau-projet
bash tools/bootstrap.sh "Mon nouveau projet" "ce que fait le projet"

  
bootstrap.sh écrit un README.md propre au projet, remet
  STATE.md à zéro, purge les passes et rapports de l'exemple, ajoute le gabarit comme
  remote kit, crée les cinq labels et vérifie l'outillage
  (agy, node, script, python3).

18 · Dépannage

  
Sortie vide alors que le code de sortie est 0
    
C'est le bug non-TTY d'agy -p. Le kit l'enveloppe déjà dans un pseudo-TTY et relance
    une fois si la sortie est vide. Si le symptôme persiste : vérifie que script est installé
    (util-linux), et n'utilise jamais agy -p nu dans un script.

    
bash
script -qec 'agy -p "PONG"' /dev/null   # Linux
script -q /dev/null agy -p "PONG"       # macOS


  
« auth timed out » dans les logs
    
Le contexte non interactif n'a pas retrouvé la session. Relance agy en interactif une
    fois pour rafraîchir le cache, puis relance la passe. Sur une machine sans écran, agy
    détecte la session distante et affiche une URL d'autorisation à ouvrir depuis ton navigateur local.


  
Passe échouée : « marqueur PASS-DONE/PASS-BLOCKED absent »
    
L'exécuteur n'a pas respecté AGENTS.md §7. C'est presque toujours le signe d'une spec
    trop large : il s'est épuisé avant de conclure. Réduis le périmètre, rappelle le marqueur
    explicitement dans la spec, et baisse le budget.


  
git worktree add échoue
    
bash
git worktree prune
git worktree list
git branch -D pass/PASS-001   # si la branche traîne encore


  
Le CI échoue sur pass-contract
    
C'est le garde-fou qui fonctionne, pas une panne. Soit le rapport de run manque ou est incomplet,
    soit l'exécuteur a touché un fichier de contrat. Dans les deux cas : ne désactive pas le job,
    fais corriger la passe.


  
Le quota hebdomadaire est épuisé
    
Le contrat vit dans le dépôt, donc l'exécuteur est remplaçable. Change AGENT_CMD
    dans .env — qwen, opencode ou aider — et relance
    la même spec. Rien d'autre à modifier.


  
L'exécuteur ne répond pas à travers le tunnel
    
Vérifie dans l'ordre : /health en local, le tunnel actif, l'URL exacte, puis le jeton.
    Une erreur 401 signifie que le jeton du client diffère de EXECUTOR_TOKEN ;
    une absence de réponse signifie que le tunnel est tombé.
